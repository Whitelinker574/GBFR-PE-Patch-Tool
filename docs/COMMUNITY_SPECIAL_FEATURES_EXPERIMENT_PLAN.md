# 社区特殊功能实验分支计划

## 1. 分支与目标

- 实验分支：`experiment/community-special-features`
- 基线：`master@8a72d10`
- 游戏基线：Granblue Fantasy: Relink DLC 2.0.2
- 目标：把近期社区中有价值的配装、战斗分析、存档诊断和实时便利能力，重做成符合本项目数据链路、生命周期、安全边界和羊皮纸主题的功能。
- 发布边界：本分支不直接发布。每项功能单独通过数据校验、自动测试、响应式截图和实机恢复验证后，才允许选择性移植到稳定线。

本计划不是把其他项目拼进当前应用。外部项目用于确认用户需求、公开行为和研究方向；生产实现必须继续使用本项目的 Wails/Vue/Go/`patch_core` 架构、统一目录、官方 2.0.2 图标和现有事务/回读机制。

### 导航先决改造

当前顶层页签依赖横向滚动，继续增加入口会降低发现性。实施新页面前先完成：

1. 顶层左栏仍只保留四个工作流，不增加第五个大类。
2. 配装优化和分享图使用配装工作台内部的二级分段导航，不占用全局页签。
3. 实时补丁保持“战斗规则 / 角色机制 / 任务便利”的现有常驻会话；空间移动和扩展因子使用独立入口，因为它们有完全不同的控制与风险状态。
4. 同组功能超过可视宽度时使用“固定当前项 + 可搜索的更多菜单”，不依赖用户猜测横向滚动。
5. 最小支持窗口继续为 `960 x 640`。任何功能不得迫使整个应用产生横向滚动；宽表和时间线只能在自己的明确滚动区域内滚动。

## 4. 页面与角色素材规划

所有新页面先完成真实流程分析和 page brief，再生成素材。角色选择以功能语义为准，不只是“没有用过”。

| 页面/模式 | 角色 | 选择理由 | 立绘动作与功能道具 | Q 版提醒重点 |
| --- | --- | --- | --- | --- |
| 库存配装优化 | 索恩 | 精确瞄准对应多条件筛选和精确求解 | 拉弓瞄准由多个官方因子图标构成的目标盘；图标本身在 UI 直接使用，不让模型重绘 | 必选条件过多可能无解；先看库存占用 |
| 因子图鉴与组合查找 | 齐格飞 | 资深战士的知识和可靠判断适合承担技能与组合资料索引 | 一手翻阅无文字的战斗手册，一手指向主/副词条分开的因子结构图 | 目录来自 2.0.2 数据；未证明的获取途径要标明 |
| 分享图工坊 | 夏洛特 | 适合成果展示、队伍分享和庆祝感 | 双手展开一张无文字的羊皮卷版式，官方角色头像和因子图标由 UI 后叠加 | 发布前检查标题、短码和二维码目标 |
| 战斗档案 | 泽塔 | 战斗数据、攻击拆分和上限压力与其定位一致 | 长枪指向训练目标旁的伤害时间线；武器必须保持一体连续 | 战报缺字段时显示未记录，不能用零替代 |
| 存档实验室 | 兰斯洛特 | 冷静、细致，适合双份记录核查 | 左右对照两册无文字记录簿，用细线标出差异；双剑完整收纳 | 原始未知字段先只读，不允许猜测写入 |
| 空间与移动 | 菲迪埃尔 | 漂浮感与坐标/重力主题天然匹配 | 悬浮于三轴定位环上，手势指向一个明确坐标锚点 | 飞行不等于无碰撞；断开前恢复重力 |
| 音频控制 | 冈达葛萨 | 强烈而有辨识度的声音表现适合说明独立音量与混音 | 在一个有明确推子轨道的机械混音台前调整单个推子，双拳和控制台互不穿插 | 设置作用于后续语音事件；静音角色前先确认选择 |
| 扩展因子实验室 | 贝阿朵丽丝 | 高收益和高风险的实验功能与其性格契合 | 操作一组有固定槽位的因子托盘；槽位、连接和数量必须物理清晰 | 仅单机；未知版本或冲突时必须停用 |
| 掉落规则实验 | 加兰查 | Infinity 首领与终盘掉落主题直接相关 | 检查一个由祝福石与召唤石组成、分成明确格位的战利品托盘 | 这是掉落规则模组，不是直接向存档添加物品 |

预留未使用角色：珀西瓦尔。外部调研确认新模块前不提前消耗素材身份。

每个页面必须执行 `generate-gbfr-relink-portraits` 工作流：

1. 读取真实组件、状态、API、错误和成功态。
2. 从 2.0.2 语义素材库检索零到三个精确游戏对象参考。
3. 保存并校验 page brief。
4. 先审线稿，再生成透明立绘和 Q 版贴纸。
5. 在原图和实际 150 x 160 贴纸尺寸检查身份、肢体、武器、道具、透明边缘和功能表达。
6. 只把验收通过的 WebP/PNG 放进生产资产；密钥、工作流、生成中间文件不得进入仓库。

分享图还有一套独立于“页面引导角色”的角色素材库。夏洛特只负责分享图工坊页面的引导，不会出现在其他角色的导出图片里。导出素材按 29 个视觉身份建立映射：

- 官方游戏小头像作为永远可用的身份锚点；
- 每名角色一张统一安全边距、但动作和气质不同的透明分享主题立绘；
- 每名角色一张“展示自己的配装卷轴”的专属 Q 版贴纸，贴纸不烘焙文字；
- 每名角色各自的 UI 气泡短句、姿势说明、光学缩放和锚点配置；
- 未完成或未通过身份/肢体/边缘验收的角色自动退回“头像 + 武器 + 纹章”模板，绝不显示其他角色的立绘或贴纸。

29 名角色素材分批生成，每批先做索引、缩略图总览和身份交叉检查。生产包按当前选中角色懒加载，不在配装工作台启动时一次解码全部立绘。

## 5. 统一视觉与组件规范

### 主题

- 继续使用 `style.css` 的浅色羊皮纸、胡桃木、黄铜和墨色语义令牌。
- 不引入深蓝/紫色主色，不为单个新页面重定义全局色板。
- 主选中态保持棕金实心；青色只表示信息，绿色只表示成功，红色只表示危险/恢复失败。
- 正文和数据继续使用现有 `--font-ui`、`--font-display`、`--font-data`，不额外下载字体。
- 圆角使用 `--radius-sm/md`；不增加大面积悬浮卡片和卡片套卡片。

### 可复用组件

计划补充以下项目级组件，避免六个页面重复造样式：

- `UiSubpageNav`：配装工作台二级分段导航，支持固定当前项和更多菜单。
- `GameAssetIcon`：统一角色、武器、因子、技能、召唤石图标与缺失态。
- `SourceBadge`：标明存档、实时、Logs、估算、未记录和虚拟来源。
- `TraitLevelRow`：显示投入等级、有效等级、上限、溢出和逐来源展开。
- `ExperimentGate`：游戏版本、单机确认、恢复证据和功能开关的统一门禁。
- `EmptyEvidenceState`：不把缺失字段显示为零，也不生成误导性默认值。
- `FixedCanvasPreview`：分享图离屏固定尺寸渲染和缩放预览。

所有图标优先使用项目已同步的 2.0.2 官方 PNG；熟悉的操作使用 Lucide 图标，按钮必须有工具提示和可访问名称。

## 6. 功能实施计划

### 阶段 A：实验框架与 UI 基线

1. 为实验分支增加本机功能开关，默认关闭高风险实时能力；开关不写入游戏或存档。
2. 抽出二级导航、来源标记、实验门禁和图标组件。
3. 增加页面级延迟加载和素材预热，避免继续拉长配装工作台首次打开时间。
4. 建立 Playwright 溢出检查：扫描可见元素的边界、页面横向滚动、按钮文字裁切和弹窗越界。

完成标准：不添加业务功能时，现有全部页面视觉和测试保持不变。

### 阶段 B：分享图工坊

入口放在单套配装预览和网页详情页，不要求用户先进入独立设置页面。

首批模板：

- `航海日志横版`：1920 x 1080，适合 QQ 群和桌面预览。
- `角色图鉴竖版`：1440 x 1920，适合长图传播。
- `紧凑方图`：1600 x 1600，适合头像流和移动端预览。

用户可选内容：

- 标题、简介、作者署名（可空）、游戏版本、生成日期；
- 角色头像、武器、12 个因子、专精方向、武器技能/祝福、召唤石、合并技能等级；
- 在线短码和二维码；关闭网络分享时只显示离线标记，不把超长离线码硬塞进二维码；
- 背景强度、信息密度、横/竖模板和是否显示项目标识。

角色立绘策略：

- 默认“精确角色版”从 29 人分享素材库读取当前角色通过验收的透明立绘和专属贴纸；没有时退回头像、武器和纹章，不借用其他角色立绘。
- 可选“工具主题版”允许使用项目常用功能立绘作为淡化背景，并明确标为装饰主题。
- 图标和文字由 HTML/CSS 绘制，图片模型不负责生成小字、二维码或游戏图标。

技术路线：固定尺寸离屏 DOM -> 2x 像素密度 PNG；应用端通过 Wails 剪贴板/保存 API 提供可靠复制和下载，网页端使用浏览器 API 并保留下载回退。二维码只编码 HTTPS 分享链接，生成后在测试中解码并比对原链接。

完成标准：三模板在中文/英文、最长合法名称、满 12 因子和缺失字段下均不溢出；导出的 PNG 像素尺寸、二维码、图标和文本与预览一致。

### 阶段 C：因子图鉴与组合查找

该页面不是另一个编辑器，而是当前因子目录的可审计浏览入口：

- 按中文/英文名、内部技能 ID、外壳、主词条和副词条搜索；
- 显示因子外壳、允许的主/副词条池、单词条/双词条形式、自然等级和 2.0.2 技能上限；
- 展示来自游戏表能够证明的获取类别；无法从本机表证明的社区说法标为“待核对”，不混进正式目录；
- 组合查找输入两个目标技能，返回合法外壳和方向，不生成不存在的“两个主因子拼在一行”的名称；
- 可从图鉴把技能送入库存优化目标、当前配装编辑器搜索或分享图说明；
- 目录和图标全部从本项目 2.0.2 数据生成并带数据版本，不读取 CT 表作为运行时真值。

完成标准：单词条、普通 V/V+、仅 `+` 后缀和特殊无后缀因子的名称规则都有夹具；中英文切换无串词；图鉴合法组合与存档/内存/配装三个入口的目录一致。

### 阶段 D：真实库存配装优化

数据源只读取用户选择的存档，复用当前存档选择、因子目录和配装预览，不保存整份原始存档副本。

目标模型：

- 必须满足：有序、可重复；
- 可选目标：有序、可重复；
- 禁止出现：命中主/副词条即淘汰；
- 尽量避免：不淘汰但降低排名；
- 主词条方向：基础、攻击、防御等类别；
- 角色与方案库存预留：已确认方案占用真实实例数量。

求解结果：

- 精确 Top 10，不返回近似结果冒充精确结果；
- 显示每枚因子的真实库存数量、已装备、已预留和剩余；
- 支持在真实剩余库存内手动替换；
- 每项结果可进入现有完整配装预览，再通过现有分项导入弹窗写入目标槽位；
- 分享“目标条件”时，接收方使用自己的库存重新计算，不传播伪造实例引用。

后端先实现分组库存、约束规范化、确定性排序、分支限界/动态规划和穷举小样本 oracle。达到内存/时间阈值时返回明确超时，不静默降低正确性。

完成标准：随机小库存与穷举结果完全一致；重复目标、单词条因子、同名不同等级、跨角色预留和库存不足均有回归测试；求解过程不得修改存档。

### 阶段 E：战斗档案与技能上限分析

第一步复用已经支持的 GBFR Logs、Endless、Relink Logs、SkyMeter 数据库/JSON，不新增注入：

- 场次列表按时间、任务、敌人和角色过滤；
- 队伍 DMG、DPS、占比、战斗时长；
- 角色技能伤害、次数、占比和时间线（源数据存在时）；
- 配装快照与当前技能等级合并；
- 技能投入等级、有效上限和溢出来源；
- 缺失字段统一显示“未记录”，不显示零条来源。

第二步才研究当前会话伤害采集。需要独立协议版本、固定大小事件、环形缓冲区、掉包计数、进程退出清理和与配装捕获 Hook 的共存测试。实时采集不能阻断现有只读配装检测。

不在配装编辑器里加入完整招式轮转“实战数据台”；战斗复盘是只读监测的独立页面。

完成标准：至少用三个不同 Logs 版本的数据库和 JSON 夹具验证；历史数据离线可用；分页、筛选和时间线在 10,000 场记录下仍保持响应。

### 阶段 F：存档实验室

首版严格只读：

- 同时选择两个存档，按向量、记录、字段和值显示新增/删除/变化；
- 逻辑视图优先，未知记录保留 Hash、原始类型、长度和相对位置；
- 支持 Hash、内部名、中文/英文名和字段类型搜索；
- 导出脱敏 JSON/CSV 差分，不包含用户名、绝对路径和真实 SteamID；
- 可从差分跳转到已有逻辑编辑页面，但不直接写未知字段。

后续只有已证明的字段才可加入白名单编辑器，并继续使用当前原子替换、校验和修复、自动备份和回读验证。

完成标准：相同存档差分为空；单字段夹具精确定位；损坏、截断和向量越界输入只报错不崩溃；原文件始终以只读方式打开。

### 阶段 G：小型实时便利补丁

这些能力接入现有常驻补丁会话，不创建各自的悬空进程句柄。

#### 训练场外伤害上限百分比

- 归入战斗规则补丁；
- 只改变显示条件，不改变伤害、上限或存档；
- 必须验证训练场内原行为、任务内显示、过场/菜单无副作用和关闭后的原字节恢复。

#### 敌人 HP / 奥义槽小数精度

- 归入战斗规则的“界面精度”，与伤害上限百分比共用一块紧凑设置；
- 敌人 HP 与奥义槽可分别开关，精度 0-4 位；
- 只改变 UI 文本格式，不改变实际 HP、奥义值或伤害；
- 等级、整数 HP 等复用相同文本函数的界面必须保持原样。

#### 普通任务等级同步

- 复用游戏已有的等级/战力调整逻辑，不直接改角色存档等级；
- 默认关闭并明确显示任务范围，未知任务类型保持原行为；
- 联机平衡影响需要单独实机评估，未完成评估前仅允许单机实验。

#### 极沌空域快速等待

- 归入任务与便利补丁；
- 首版只缩短已验证的等待计时器，不宣称自动领奖或自动重进；
- 记录原始配置和当前活动计时器，启用失败必须原子回滚；退出、更新、断连前必须恢复。

#### 无限任务辅助模式

- 先核对当前“无视限制启用辅助模式”是否已经覆盖 Infinity 类型；
- 已覆盖则只补实机证据和 UI 说明，不重复实现；
- 未覆盖才独立定位任务类型与禁用分支，默认仅单机，未知任务/会话状态保持游戏原行为。

#### 重镶祝福时返还旧祝福石

- 归入任务与便利补丁中的物品保护；
- 在确认重镶前保存旧祝福石的完整种类、三词条、等级和状态，成功完成后才返还；
- 取消、失败、背包满、对象变化或重复事件不能返还，也不能复制出第二份；
- 返还后必须同时核对武器的新祝福和背包中旧祝福的完整记录。

#### 自动复制房间 ID

- 只在游戏创建/加入会话且 ID 得到完整校验后写入系统剪贴板；
- 提供关闭开关和一次性“复制当前房间”按钮，不轮询污染剪贴板；
- UI 不记录或上传房间 ID。

#### 主线队伍自由替换古兰/姬塔

- 归入角色机制补丁；只放宽主线强制队长检查，不修改存档解锁或剧情进度；
- 不认识的剧情状态、强制演出或教程阶段保持游戏原行为；
- 关闭后恢复队伍规则，不自动改写当前队伍。

完成标准：每个补丁都有精确原字节、唯一签名、启用回读、关闭回读、进程重启、页面切换、程序退出和不支持版本测试。

### 阶段 H：空间与移动

新页面包含：

- 当前角色和 `X/Y/Z` 连续读取；
- 输入坐标后一次性传送；
- 本地命名书签和原点返回；
- 世界轴飞行，速度 0.1-1000，默认 8；
- 飞行时的重力关闭与停止/断连时的强制恢复；
- 城镇镜头最大距离、视点高度和缩放步长；
- 紧急停止热键和清晰的当前按键提示。

第一版不声称穿墙，也不实现未验证的无碰撞。相机相对移动只有在相机基向量得到独立实机证据后才加入；否则 UI 明确写“世界轴”。

页面必须绑定当前进程身份和角色对象生命周期。换角色、读档、退出菜单、加载场景或对象指针变化时立即停止飞行，不继续写旧对象。

完成标准：两名角色、切角色、退出任务、读档、游戏退出和程序异常关闭均不残留重力修改；坐标输入拒绝 NaN/Inf/越界；按键轮询不抢占应用输入框焦点。

### 阶段 I：掉落规则实验

社区项目证明了两种与“直接改存档”不同的需求：让游戏的自然流程只产出用户选定的祝福石，或让 Infinity 首领按配置产出召唤石。该能力不能伪装成现有召唤石/祝福石存档编辑。

首版采用本机生成模组，而不是把提取后的游戏表打包进仓库：

- 从用户自己的 2.0.2 `data.i` 和表文件读取原始行；
- 祝福石模式可选择类型、主词条 Lv20、副词条 Lv15/Lv10，并保留游戏内炼成流程；
- 召唤石模式可选择首领、技能、装备加成和允许的自然概率档；
- 生成只包含必要变更的本机重定向模组，并记录输入哈希、输出清单和恢复清单；
- 安装前显示“游戏数据模组”身份、单机提示和与其他 Mod 的覆盖冲突；
- 不修改原始 `data.i`，优先通过现有 Mod Manager/重定向器部署；停用时移除本工具拥有的输出。

完成标准：相同输入可重现相同输出；不匹配的游戏表、缺少 Mod Manager、已有同路径覆盖和游戏运行中部署都必须阻止；还原后文件清单和原始哈希一致。

### 阶段 J：音频控制

页面按“角色语音 / UI 音效 / 预设”组织，不替换游戏音频文件：

- 每个可识别角色独立 0-100% 音量，游戏 Voice Volume 仍是总音量；
- 日语/英语语音库分别扫描，角色映射来自用户当前安装档案；
- UI 音效只对已经验证的类别提供独立音量，不允许一个未知事件错误静音全部界面；
- 设置变化作用于后续事件，正在播放的语音不强行截断；
- 支持本地命名预设、全部恢复 100%、只静音指定角色和诊断事件日志；
- 诊断日志默认关闭，并移除用户名、路径和不可公开的事件上下文。

实现使用版本化 Wwise `PostEvent` Hook 和事件到角色/类别的本机生成目录。无映射事件保持原音量，Hook 冲突或签名不唯一时整页保持关闭。

完成标准：中/日英语音配置、29 个视觉角色、露莉亚/碧/谢洛等非战斗角色、菜单/战斗/剧情切换、热更新设置、退出恢复和与其他 Hook 共存均有验证；不能出现因一个角色配置导致全局无声。

### 阶段 K：扩展因子实验室

这是最后实施、风险最高的功能。它不是增加存档物理槽，而是在运行时向 trait 汇总流程注入额外来源。

首版范围：

- 每角色 1-24 个虚拟槽；
- 角色命名预设和启用/停用；
- 使用官方因子、词条和图标目录；
- 显示物理 12 槽、虚拟槽和最终技能等级的独立来源；
- 身份、数量、冲突和技能上限检查；
- 可选择“仅引用实际库存”或“实验性合成”，二者在 UI 和导出中永久区分；
- 分享/上传时必须标记为虚拟扩展配装，不能伪装成正常 12 槽配装。

实现必须使用独立、版本化的 `patch_core` 能力和共享内存协议；功能停用时先停止读取配置，再恢复入口字节并释放远程资源。未知游戏版本、签名不唯一、协议版本不匹配或其他 Hook 占用入口时保持关闭。

默认只允许单机并保持关闭。任何在线可用性都不能作为本项目承诺，也不能默认开启。

完成标准：0/1/12/24 槽、重复词条、单词条因子、角色切换、预设切换、配装页面切换、场景加载、与配装捕获/怪物 Hook 共存、断开和崩溃恢复均通过；未证明恢复完整前不进入稳定线。

## 7. 响应式与视觉验收

每个新增页面和弹窗至少检查：

- 960 x 640（应用最小尺寸）
- 1024 x 768
- 1280 x 720
- 1366 x 768
- 1600 x 900
- 1920 x 1080
- 2560 x 1440
- Windows 100%、125%、150% 显示缩放

自动检查：

- `documentElement.scrollWidth <= clientWidth`；
- 可见按钮、标签、输入框和卡片边界不越过其滚动容器；
- 最长中英文名称不覆盖等级、图标或操作；
- 固定画布预览只缩放外壳，不改变导出布局；
- 弹窗最大高度受视口约束，主操作始终可滚动到达；
- 加载、空、错误、无权限、不支持版本和恢复失败状态都有真实布局；
- 页面只保留一个主滚动容器，局部宽表/列表有明确的局部滚动。

截图由 Playwright 在浏览器壳完成，再用实际 Wails EXE 检查 Windows 缩放、系统字体和 WebView2 差异。涉及 3D/实时画面的功能还必须配合游戏截图和状态回读，不能只凭 DOM 测试宣布完成。

## 8. 测试与合并门槛

每项功能独立提交，禁止一个提交同时混入多个 Hook、UI 重构和目录更新。

通用门槛：

1. Go 单元测试、边界/模糊输入测试和事务回读测试。
2. 前端状态、国际化、长文本、键盘操作和响应式合同测试。
3. Cloudflare Worker/在线图鉴测试（涉及分享时）。
4. `patch_core` Release/Debug x64 构建和协议版本测试（涉及 Hook 时）。
5. `go test ./...`、前端完整测试、生产构建和 Wails EXE 启动检查。
6. 受支持 2.0.2 EXE 哈希、签名唯一性、原字节和恢复证据。
7. 实机正向、错误顺序、切角色、切页面、读档、退出任务、重启游戏和异常断开测试。
8. Playwright 多尺寸截图、横向溢出扫描和像素非空检查。
9. 新增第三方依赖、算法参考和素材来源同步到 `THIRD_PARTY_NOTICES.md`。

选择性合入稳定线时使用单功能提交或干净的 squash，不合并整个实验分支历史。虚拟因子槽、实时 DPS Hook 和飞行功能即使代码完成，也必须单独经过更严格的实机恢复审计。

## 9. 推荐实施顺序

1. 阶段 A：实验框架、二级导航和溢出测试。
2. 阶段 B：分享图工坊。风险最低，能快速验证新视觉组件和二维码链路。
3. 阶段 C：因子图鉴和组合路径，先统一所有入口的数据语言。
4. 阶段 D：真实库存配装优化。价值最高，但先以只读求解闭环。
5. 阶段 E：基于现有 Logs 的战斗档案，不先做新 Hook。
6. 阶段 F：只读存档差分，为后续所有结构研究提供证据工具。
7. 阶段 G：逐个加入小型补丁，每个单独实机验证。
8. 阶段 H：坐标、飞行和镜头，先世界轴和可靠恢复。
9. 阶段 I：本机掉落规则模组，先证明构建与恢复，不修改原始归档。
10. 阶段 J：音频控制，先建立本机事件目录再接 Hook。
11. 阶段 K：虚拟因子槽，作为最后的高风险独立能力。

外部社区二次调研结果会追加到本计划的候选清单，但不会自动改变以上安全顺序。
