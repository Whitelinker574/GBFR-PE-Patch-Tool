## 对项目维护的直接含义

- 不能沿用 2.0.2 的 EXE 签名、原字节或运行时 Hook 地址并假设仍然有效；应先对 2.0.3 EXE 重新做签名与原字节校验。
- `data.i` 与多个数据归档被更新，应重新解包并与已留存的 2.0.2 基线做表级、记录级差分，重点核对项目实际读取的物品、因子、技能、召唤石、祝福、角色和任务表。
- 两份英文语音 bank 变化值得单独比对，但不能在未试听和未解析 bank 元数据前宣称修复了哪条语音。
- 运行时补丁、存档写入和数据表解析必须经过 2.0.3 的重新回读与实机验证；自动化测试通过不能替代版本兼容性证据。

### 通用 Runtime Patch 目录

对 82 个已锁定的补丁点在 2.0.3 全部可执行 PE 段重新扫描旧 AOB：

- 77 个仍唯一命中，补丁目标原字节一致；
- 3 个仍唯一命中，但完整 8 字节指令不同；
- 2 个旧 AOB 不再命中；
- 所有补丁地址均发生迁移。

3 个完整指令变化点是 RIP 相对位移变化，当前看到的指令语义仍相同：

- 目录 ID 14：防止无痛肉身衰减；
- 目录 ID 28 site 0：无限极彩羽翼；
- 目录 ID 35：无限刃重槽。

旧签名失效的两点：

- 目录 ID 45 site 1：无视召唤限制；
- 目录 ID 54 site 4：MSP / 境界点数不减。

ID 54 的新版邻近代码仍能找到同类 `neg r13d` 逻辑，但没有建立新的唯一、可恢复签名；ID 45 site 1 也未完成重新定位。不能按近似地址猜测写入。

尽管多数 AOB 仍能匹配，正式工具的通用 Runtime Patch 写入会先校验完整 2.0.2 EXE SHA-256；2.0.3 会被明确拒绝。这是当前应保留的 fail-closed 行为。

### 内置 `patch_core.dll`

从当前 `patch_core` 源码抽取的 26 条动态签名在两个版本中的结果：

- 2.0.2：26/26 唯一命中；
- 2.0.3：26/26 唯一命中；
- 命中地址全部迁移。

这些签名覆盖镜头、伤害捕获、部分 QOL 和队长替换等入口。唯一命中只说明“可能重新定位”，不能替代新版原字节、恢复路径、PID/creation-time 生命周期和实机测试，暂不能据此开放 2.0.3。

### 已确认失效的固定 RVA

虚拟因子仍使用多处 2.0.2 固定 RVA，包括 trait apply/category/fetch、`GetGemData` 和全局管理器。旧 RVA 在 2.0.3 已落到无关指令，明确不兼容。

实时因子、实时祝福、召唤石背包/保存函数、队友配装、选中物品、角色实时面板、空间移动/重力、药水和部分早期角色工具都包含固定 RVA、固定全局或 2.0.2 布局假设。它们在完成新版地址、原字节、恢复和实机回读前都应视为不兼容。

### `data.i` 天然掉落部署

天然掉落部署会同时校验：

- EXE 文件名；
- 2.0.2 的精确文件大小；
- 2.0.2 EXE SHA-256；
- 2.0.2 版本的部署 manifest / transaction journal 身份。

所以当前 2.0.3 安装会在写 `data.i` 前被拒绝，不会拿旧模板静默覆盖新版索引。虽然本次目标掉落表字节未变，也仍需先证明新版 `data.i` 打包、恢复和游戏实际加载链，才能更新门禁。

## 当前功能边界

### 可继续使用的静态依据

- 内置 2.0.2 因子、祝福、召唤石、武器、技能、伤害上限和规则目录仍与 2.0.3 解包表一致；
- 不依赖游戏进程和 `data.i` 写入的浏览、计算、配装 JSON、短码和本地分享功能没有因本次表差分发现新的数据冲突；
- 离线存档解析器没有发现 schema 变化证据，但仍需用 2.0.3 实际保存后的复制存档做打开、写入、重新打开和重启回读。

### 暂不可在 2.0.3 开放

- 通用 Runtime Patch 目录的全部写入；
- `patch_core.dll` 的镜头、音频、QOL、伤害捕获和虚拟因子运行时；
- 实时因子、实时祝福、实时召唤石；
- 持续队友配装检测和实时配装读取；
- 实时角色面板、空间移动、重力和方向键移动；
- 选中物品捕获、药水/货币和怪物增强等运行时能力；
- 天然掉落 `data.i` 部署。

现有正式工具应继续把这些能力锁定在已验证的游戏 2.0.2，不能只因为静态表未变或某个 AOB 仍唯一命中就改为支持 2.0.3。

## 尚需完成的 2.0.3 验收

1. 以 2.0.3 实际保存过的存档副本完成解析、原子写入、重新打开和游戏重启回读。
2. 为所有运行时路径重新建立新版地址、完整原字节与恢复证据，不能只迁移 RVA。
3. 对每个 Hook 验证 `{PID, creation time}`、owner/lease、断开和应用退出恢复。
4. 验证 `patch_core.dll` 在切角色、切场景和多 Hook 长时运行下的行为。
5. 用新版 `data.i` 完成隔离部署、游戏实际加载和完整恢复测试。
6. 对两份路西法英文语音 bank 做事件级差分或实际试听。

## 证据边界

- Steam app manifest 和 content log 是 Steam 客户端生成的一手安装记录；文件版本与 SHA-256 来自当前官方安装文件。
- 表级差分来自本机 2.0.2 锁定基线与当前官方 2.0.3 安装，使用相同解包工具后逐文件 SHA-256 比较。
- EXE 结论来自可信 2.0.2 本机备份和当前官方 2.0.3 文件的 PE 可执行段扫描；候选新 RVA 不是兼容性授权。
- SteamDB 未作为结论来源。
- 本文没有采用社区帖子、视频、CT 表或第三方工具更新说明作为 2.0.3 官方变化证据。
- 后续若 Cygames 发布正式 patch notes，应以新公告补充或修订本文，不能反向把当前未知项写成已确认。
