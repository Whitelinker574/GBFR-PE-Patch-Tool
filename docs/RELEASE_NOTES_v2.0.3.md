# v2.0.3｜智能配装、队友采集、分享图与存档实验室

v2.0.3 是从 v1.92.0 以来的一次完整功能更新。它不只是增加几个入口，而是把“找配装、看配装、部署配装、采集队友配装、分享配装、核对存档、恢复修改”串成了可以正常走完的用户流程。

如果你只想先体验三件事，建议从这里开始：

1. 打开任意角色配装，在因子区域切到“按技能配装”，输入目标技能和等级；
2. 进入“配装采集与复刻”，手动开启队友配装持续检测；
3. 从自己的配装生成分享码或分享图，再到在线图鉴查看实际展示。

## 一、角色配装：从手动填写到按目标自动完成

### 智能配装回到正确的位置

“按技能配装”现在就在角色配装详情的因子区域上方，与手动配装使用同一套编辑器。输入目标后，结果会直接回填十二个因子槽，先成为草稿，不会绕过确认直接改存档。

### 目标技能不再限制四项

你可以添加任意数量的技能目标。求解器严格按列表从上到下处理：

- 优先满足排在前面的目标；
- 十二槽不足时，从无法继续的那一项开始明确提示；
- 已满足、部分满足和未满足会分开显示；
- 重新排序目标即可改变取舍，不需要删除后重建。

### 先用真实背包，缺什么再说明

求解会优先使用目标存档中真实存在、互不重复的因子实例，并保留每颗因子的 SlotID。背包不足时，方案会列出需要制造的合法因子和数量；只有用户确认后才会创建新实例，不会静默制造，也不会让多个槽位引用同一个对象。

### 29 名角色的参考路线与方向分支

每名可操作角色都有至少一套从可读视频帧整理的十二槽参考路线，并可从该路线派生：

- 高血/低血天星攻击；
- 防御、昏厥和续航；
- 药水/复活；
- 闪避循环；
- 双蟹套装等方向。

路线会核对角色专属因子、DLC 因子、合法外壳、固定副词条和真实等级曲线。角色特性、伤害上限、当前装备与防御端证据也会参与解释和排序。视频没有展示的武器、祝福、召唤石和专精不会被工具自行补猜。

这些路线是可追溯、可解释的参考配装，不是对每个动作、每个敌人和每种战斗条件的“绝对理论最优”承诺。

### 配装页的其他改进

- 当前实时配装继续固定在已保存预设之前；
- 因子图鉴可以把合法外壳和词条直接送入当前草稿或目标求解；
- 武器技能、祝福、召唤石、专精和因子统一进入动态技能等级与实际加成汇总；
- 四项上限突破、召唤石效果、专精效果和永久成长分别标明来源；
- 分享码导入、下载 JSON 和本地导入使用同一份规范化配装帧；
- 缺失数据继续显示“未记录”，不会压成 0 或拿其他角色的数据补齐。

## 二、Logs、队友配装与战斗档案

v1.92.0 建立了 Relink Logs 角色 JSON 一键解析、预览、选择作用域、部署和上传。本次在这条流程上继续补齐：

- 支持不同 Logs JSON 形态并统一成内部配装格式；
- 战斗档案与配装库复用同一个只读 `logs.db` 会话，不用重复选数据库；
- Logs 历史使用连续游标翻页，不使用越翻越慢的 OFFSET；
- 外部 BLOB 在 SQLite 查询层先检查长度，并且最多只取 8 MiB，再交给解压器；
- 数据库、JSON、记录数、玩家数和解压数据都有明确输入上限。

### 队友配装检测变成持续后台服务

检测默认关闭。用户点击开启后，它会跨页保持连接，直到主动关闭：

- 绑定 online 槽位、角色、武器、因子身份和连续快照；
- 连续三次一致后才把队友配装作为候选；
- 每场保存可确认的 2–3 名队友配装；
- 历史可以预览、导出、部署和上传；
- 没抓到的武器、祝福、召唤石、专精或技能显示“未记录”。

### 战斗档案与当前会话伤害

战斗档案可以查看 Logs 场次、队伍伤害、技能明细、目标和配装快照。当前会话也可以采集 2.0.2 的伤害事件、原始动作编号、上限前伤害和伤害上限。

本机、队友、宠物和召唤物的稳定归属尚未完成，所以当前会话只显示“全局未归属观测”，不会包装成个人 DPS。

## 三、在线图鉴、短码和分享图

### 图鉴交互

- 配装卡片外层可以直接点赞，再次点击取消；
- 默认按最新时间排序，也支持名称和点赞排序；
- 搜索覆盖角色、武器、因子、祝福、召唤石、专精和技能；
- 角色页缩小装饰面积，把空间留给配装卡片；
- 顶部保留 GitHub 下载入口和 favicon；
- 页面、下一页和角色资源会预取，减少翻页和切换等待。

### 上传、去重和回退

- 相同不可变配装帧会得到稳定短码，重复上传不会重复生成公开正文；
- “公开上传”开关关闭时，不会把配装加入公共目录；
- 12 位旧码只在唯一前缀匹配时兼容；
- 网络失败会给出离线长码或文件兜底，不只显示“解析失败”；
- R2 保存不可变正文，D1 保存可搜索目录；
- D1 故障时使用有界 R2 全局回退排序；超过可以证明完整性的上限会直接失败，不返回假排序。

### 分享图

桌面端分享图改为清透空域、星图与金色花纹的角色卡版式，不再使用羊皮纸底色。角色立绘更大，标题、武器、十二因子、技能摘要和二维码分别有固定区域，长文案不会再压住页脚。

桌面端提供横版 `1920×1080`、竖版 `1440×1920` 和方形 `1600×1600` 三种规格；窗口中的预览会等比缩放，但下载 PNG 始终保持所选真实像素。图片支持复制或下载，生成过程为单飞任务，连续点击不会启动多个重叠渲染。网页详情仍提供无需安装应用的快速分享图导出，使用同一份脱敏配装预览数据。

## 四、存档实验室：比较后直接在当前页处理

双存档对比不再只输出难懂的原始变化：

- 已知字段显示角色、物品或进度语义；
- 可以按类别、可复制性和置信度筛选；
- 左右存档并排查看；
- 结构一致且已确认语义的记录可以直接选择复制方向；
- 写入前显示变更单；
- 单侧新增、删除、长度变化和未知结构保持不可复制。

写入使用版本修订检查、备份、原子替换和逐字段回读。每份存档输入上限为 64 MiB，差异计算在 UI 中保持单飞。

### 命运篇章与无尽规则

命运篇章提供受限实验写入，只开放已经审计的篇章完成值和任务完成值。它证明的是存档字段事务，不是奖励领取、完整章节依赖或可见游戏效果。

25 条无尽规则提供双语只读图鉴。没有安全的部署与游戏回读链路，因此本版本不提供虚假的编辑开关。

## 五、因子、祝福和召唤石的统一合法性

- 离线因子生成、实时因子编辑、配装构造/导入和运行时复刻使用同一份 2.0.2 合法目录；
- `0xCE6C62CF` 统一显示为“怒发冲冠 V+”；
- 固定外壳会恢复正确主词条并清除不兼容副词条；
- 如果副词条在游戏中不会生效，提示会直接说明它会被游戏忽略或替换，并要求清空/改选；
- 祝福离线、实时和配装导入统一拒绝重复词条、类型不匹配和等级曲线溢出；
- 因子和祝福允许使用真实曲线支持的最高等级，不再套固定 15/20 限制；
- 召唤石类型更换会创建新 SlotID、迁移装备引用并在写后重新开盘验证。

## 六、天然掉落和游戏文件

召唤石、Transmarvel 因子、祝福石和已验证普通物品奖励使用应用内置的十一张 2.0.2 精确表，不再要求用户自己寻找解包文件。

新的紧凑流程是：

1. 选择种类；
2. 选择主词条与副词条，或搜索普通物品；
3. 加入待部署清单；
4. 批量核对；
5. 部署或恢复。

`data.i` 部署会检查冲突、保留无关字段、备份原文件、清理旧生成登记、验证生成表并支持一步恢复。

普通物品目前只接入无尽模式“锻造师奖励”这一条已验证奖励包路径。它不是全局任务/敌人/宝箱/活动掉率修改。天然因子、召唤石掉落、祝福石锻造和普通物品奖励的实际游戏结果仍待现场验收。

## 七、运行时功能和导航

左侧目录按常用流程重新分为：

1. 存档与配装；
2. 游戏内即时编辑；
3. 配装采集与复刻；
4. 单机运行时工具；
5. 游戏文件、诊断与设置。

同组功能全部平铺为可横向滚动的标签，不再藏进“更多”。收起目录按钮与返回主页分离，常用因子、祝福、召唤石和配装入口排在前面，低频诊断放在最后。

### 运行时生命周期

- 后台采集、补丁、音频、镜头和运行时会话不会因为切页静默停止；
- 标题栏持续显示仍在运行或需要恢复的会话；
- 运行时注入现在会在认领所有权和加载 DLL 前，核对精确的 2.0.2 EXE SHA-256；
- 所有会话绑定 `{PID, creation time}`，防止 Windows 复用 PID 后误接管；
- F12 可以集中停止采集、移动和内置运行时并执行恢复。

### 已开放或保留实验标识的能力

- 显示精度、房间 ID 自动复制和主线队长替换；
- 坐标书签、受限传送、按住方向键进行世界轴移动和独立重力控制；
- 角色语音/UI 音效混音与城镇镜头；
- 当前会话全局未归属伤害事件；
- 怪物血量、昏厥和 Overdrive 控制；
- 极沌空域规则与计时参考。

世界轴移动加重力抑制不等于穿墙，应用没有把它命名为 noclip。

### 正式版保持禁用的候选

以下候选有安装/恢复或静态入口证据，但仍缺关键可见效果样本，所以 v2.0.3 不允许新开启：

- 冷却倍率与无冷却；
- 伊欧/巴萨拉卡/冈达葛萨共享蓄力；
- 候选怪物全队伤害倍率；
- 标记为 `candidate_*` 的运行时补丁；
- 新的虚拟因子运行时会话。

旧测试版如果留下由本工具拥有的会话，正式版仍提供恢复通道。普通任务等级同步和重镶返还祝福石也继续保持硬禁用。

## 八、界面和性能

- 羊皮纸、黄铜、旧书层次统一到共享页面、卡片、按钮、输入框和分段标签；
- 标签改为平面下划线状态，不再出现单页独有的凸起按钮；
- 页面说明统一回答“做什么、先点什么、数据写到哪里、怎么恢复”；
- 最小支持 960×640，表格和时间线在自己的区域滚动，不让整个应用横向溢出；
- 页面代码、立绘和贴纸按需加载，目标资源准备好前保留旧画面；
- 配装求解移入 Web Worker，新任务会终止旧任务；
- 分享图和存档差异使用单飞；
- 隐藏页面暂停重复 UI 轮询，但后台安全恢复和配装检测不降频。

参考机打包版在 960×640 与 1280×800 的 50 次热切页中，P95 均低于 300 ms。两种语言、七种窗口尺寸和三档缩放共完成 1,176 个浏览器壳页面场景检查。

## 九、升级与恢复建议

- 下载正式版本化 EXE 或 ZIP，不要把它与旧测试版文件混放；
- 重要存档先自行复制一份；
- 离线写入时完全退出游戏；
- 实时功能使用完后点击“停止/恢复”，再退出工具；
- 如果旧测试版曾开启音频、镜头或其他运行时会话，先用原测试版或 v2.0.3 的恢复入口停用，再重启游戏；
- 游戏更新后暂停使用实时写入，等待仓库确认兼容。

## 十、发布验证

正式发布需要同时满足：

- 前端全量自动化测试；
- Go 全量测试；
- loadout-share Worker 测试；
- `go vet -unsafeptr=false ./...`；
- `staticcheck -checks 'all,-ST1003,-ST1005' ./...`；
- `git diff --check`；
- 原生 `patch_core.dll` Release x64 重建；
- Windows amd64 Wails 生产构建；
- 正式 EXE 启动与响应；
- 包体预算、敏感信息、临时产物和许可文件检查。

最终测试数量、正式提交、产物 SHA-256 和下载链接以 GitHub Release 页面为准。
