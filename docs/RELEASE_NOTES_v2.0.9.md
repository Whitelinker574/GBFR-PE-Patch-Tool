# v2.0.9 更新说明

这一版主要解决“功能已经开启，但用户不知道它是否还在运行”和游戏 2.0.3 下部分运行时功能状态失真的问题。所有需要持续连接游戏的功能仍然默认关闭；只有用户主动开启后才常驻。

## 常驻功能现在一眼可见

- 配装检测、虚拟因子、角色语音、城镇镜头以及运行时补丁开启后，会在窗口顶部显示“已开启”。
- 切换页面不会停止已开启的功能；点击顶部状态项会返回对应页面，方便查看和关闭。
- 同时开启多个补丁时，状态栏会显示具体名称；数量较多时会合并显示并支持横向滚动，不会挤掉窗口按钮。
- 游戏退出并重新启动后，旧进程留下的状态不会再冒充当前游戏仍在运行。
- F12 会恢复本工具管理的运行时功能；停用后对应状态项立即消失。

## 配装检测与队伍快照

- 配装检测继续保持默认关闭，用户点击开启后才会持续观察当前队伍。
- 只读 Party 生命周期观察器已经接入检测流程，稳定的网络候选会与现有内存快照合并后进入配装检测页面。
- 合并时要求因子槽数量一致，避免把缺槽或不同结构的快照误认为同一套配装。
- 没有进入任务或尚未形成稳定候选时，页面会继续显示等待状态，不会用本机或其他槽位的数据补空。

## 游戏 2.0.3 运行时修复

- 镜头、角色语音和虚拟因子状态改为同时核对安装、所有权、游戏 PID、创建时间和运行状态；上一局的状态文件不会让页面误报“正在工作”。
- 原生运行时恢复仍按回调停止、原字节恢复、回调排空的顺序执行。
- 虚拟因子、角色语音、镜头、配装检测与两项运行时补丁完成了同开短时压力测试；页面反复切换时状态保持，F12 后四套原生运行时均回写为 `inactive`，游戏进程保持响应。
- 角色语音页把原来容易误解的复选框改名为“诊断日志”；它默认关闭，只在排查声音归属时使用，真正的开启和停用仍由右侧按钮完成。

## 虚拟因子页面布局

- 常见窗口宽度下改用单列工作区，先看当前角色槽位，再选择背包中的真实因子实例。
- 底部应用区允许按钮换行，缩小窗口或使用 Windows 缩放时也能看到“停用并恢复原技能读取”。
- 虚拟因子仍只额外读取 1–8 个真实库存实例，不会把存档的物理 12 槽扩容。

## 天然掉落与任务奖励

- 普通玩家常用的全任务普通物品倍率与高级指定掉落配置分开显示。
- 因子、祝福石、召唤石和普通物品统一加入同一份待部署清单；每一行自行决定数量，不再要求先理解互斥的“混合模式”。
- 实时任务奖励倍率与离线指定清单各自作用于不同来源，不会叠乘。
- 当前公开证据仍只能证明倍率修改本机结算。尚未证明未安装工具的 PC 或 PlayStation 队友会收到并永久保存同样的倍率奖励，因此本版没有加入“队内通用”开关。

## 使用提醒

- 运行时功能均默认关闭，请只开启当前需要的项目。
- 发现异常时先按 F12，再查看顶部状态项是否已经全部消失。
- 配装检测需要实际队伍形成连续稳定快照；仅显示“观察器已连接”不等于已经捕获到队友完整配装。
