# DLC 2.0.2 implementation status

This page separates implemented behavior from open calibration work. “Implemented” means the code path and automated verification exist; “field-verified” additionally requires a repeated observation against the running game.

## Implemented and covered

| Area | Current state |
| --- | --- |
| Multiple save slots | Save discovery is shared by offline editors and displays each detected slot independently. |
| Offline transaction safety | Backup, checksum repair, temporary output, atomic replacement and readback are implemented. |
| Sigil catalogs | Offline save generation, live-memory editing, loadout construction/import and runtime loadout restore share the same strict 2.0.2 catalog. Known shells lock their table primary and accept only the audited secondary pool; duplicate, missing-required and incompatible traits fail closed in both UI and backend. Exact captured legacy/share hashes remain transportable only when their trait identities and levels pass the unified catalog safety gate. DLC entries remain searchable. |
| Wrightstones | Offline save generation, live-memory editing and loadout import share the same trait catalog, duplicate rejection and skill-curve limits. Offline generation fixes slot one from the selected wrightstone type; live editing preserves the captured record's first trait because it does not rewrite the wrightstone type; loadout import verifies that the stored type and first trait agree. Tier index and the independent stored state/rank field remain labelled separately. |
| Summons | Offline creation/update, live editing and loadout editing share catalog options. Type replacement creates a fresh SlotID, migrates equipped references and survives disk reopen; unpacked fixed-template levels are included. Natural rules remain advisory. |
| Loadout workspace | Weapons, twelve sigils, four active skills, mastery, permanent growth, Over Mastery and summons are editable. v3 single-loadout import creates twelve independent sigils, creates missing summons, and copies Master Level progress, permanent character enhancement, weapon progression, awakening/transcendence and the equipped wrightstone in one verified transaction. A missing matching weapon still blocks a partial write. |
| Pre-DLC saves | Editors remain usable when mastery/summon records are absent and do not claim that writing a record unlocks the DLC system. |
| Persistent patch pages | Combat, character and quest tabs share one owned connection; navigation does not unmount or silently restore enabled patches. |
| Automatic perfect guard | The two-site combo-continuation patch has its own original-byte guards and was re-verified in the DLC 2.0.2 field session. |
| Runtime monitoring | Solo party snapshots, selected-object monitoring and stable HP readback are implemented. Party equipment is now bound to the producing slot and online assignment; cross-slot/local-profile records fail closed instead of presenting the host's sigils as a teammate build. Three consecutive snapshots must also agree on the online character, weapon and sigil identity before a batch is considered stable. |
| Runtime sigil editing | Every write now requires the strict unified catalog path; merely observing an unknown runtime hash no longer makes it writable. The locked 2.0.2 `GEEN_109_24` row is cataloged as the official `怒发冲冠 V+` shell with fixed `怒发冲冠` primary and exact type-lot-15 secondary pool. Selecting a shell auto-restores its fixed primary and clears an incompatible secondary; the final live write, offline save write and loadout transaction repeat the same validation, so a stale UI or imported payload cannot reintroduce the invalid combination. |
| Natural Transmarvel sigils and item rewards | The experimental natural-drop page now joins the locked 2.0.2 `gem.tbl` against the unified sigil catalog, distinguishes native Transmarvel entries from verified real rows that can be added to its pools, and validates any pinned secondary trait against that sigil's exact allowed set. The shared gacha tables are patched transactionally alongside summon/wrightstone selections, with `data.i` backup and restoration unchanged. Regular catalog items have one separately verified route through `reward.tbl`, `reward_lot.tbl` and `endlessmode_package.tbl`: the user can add bounded quantities and weights to the specific Endless Mode “Forger's Bounty” package. This is not a global item-drop override; other quest, enemy, chest and event reward routes remain disabled until independently verified. Table generation and rollback tests pass, while actual in-game Transmarvel rolls and Forger's Bounty results remain external acceptance boundaries. |
| Online loadout sharing | Short-code publish/download uses a conservative one-shot transport and retries transient connection resets with a user-facing offline-code fallback message. Public catalog reads use a D1 search index with stable time/name/like cursors; publishing dual-writes the immutable R2 payload and D1 summary. A D1 outage falls back to a bounded complete R2 metadata scan that preserves the same global time/name/like ordering and cursor semantics, and fails closed above the 1,000-object proof limit instead of returning a misleading partial order. A token-protected bounded backfill migrates existing R2 metadata without exposing private save fields. Each detail page can also render a same-origin 1600×900 PNG, copy it through the browser image clipboard when supported, and otherwise download it locally. |
| UI/catalog icons | Character, item, weapon, sigil, summon and 261/262 playable-skill mappings use bundled official assets; `AB_PL2400_09` has no matching 2.0.2 PNG and uses the neutral fallback. |
| Loadout research workspace | The share workshop stays with each expanded preset, while “manual loadout / skill-target loadout” now switches directly in the factor header of the normal character editor. Skill-target mode sends the exact user-entered levels to the solver. All 29 playable characters now have at least one dated, direct-link Bilibili route transcribed from readable frames into exactly twelve physical sigil slots. Each reviewed graduation route exposes nine directly adjacent direction choices: unchanged graduation, high-HP and low-HP Celestial offense, defense, stun, sustain, potions/revive, dodge loop, and the two-piece Dread Black Pincer Crab set. Derived directions keep every character-specific core, replace only flexible physical slots, and show their per-trait swaps and conditional costs. The crab direction requires both set traits on the two audited `+` shells with fixed Crabvestment Returns instead of presenting one piece as an active set. Fixed-route assignment is linear and inventory-first, preserves distinct SlotIDs, and can require the exact Awakening/Celestial/crab shell and recorded fixed secondary instead of substituting an arbitrary same-primary shell. The video supplies only the visible sigil blueprint; derived directions are explicitly labelled as local 2.0.2 effect-based variants, and the catalog still gates legal shells, secondary traits and levels while unseen weapons, wrightstones, summons and mastery are never invented. Its owned-first domain searches real SlotIDs and legal catalog constructions together, preferring a complete inventory-only plan even when it uses more slots and creating independent sigils only for remaining gaps. Character-direction results and community routes remain dated model/player references, not field-proven global optima. Table-evidence, audited-catalog and current-inventory domains are also calculated separately; the table domain consumes only rows carrying explicit local 2.0.2 `gem.tbl` provenance. The inventory domain reads one versioned save snapshot and jointly ranks owned weapons, their bound wrightstones, four summons, saved mastery presets and twelve real sigil instances against a gearless baseline. The snapshot itself carries the selected preset's weapon, bound wrightstone, mastery and summons, so every caller gets correct replacement diffs without reconstructing state in the UI. Results include deterministic per-domain Top 10 rows, least-change, keep-current-equipment and robust-coverage alternatives, plus `[lo, hi]` coverage-rank sensitivity. Results preserve deployable SlotIDs and exact catalog hashes, expose unresolved effect atoms, and load the selected equipment and sigils into the normal reviewed editor transaction. Large state spaces are explicitly budgeted rather than labelled global optima. |

The optimizer uses exact unpacked HP-curve nodes for Enmity, Stamina, Garrison and Stronghold and excludes unresolved intermediate `Smooth` / `SmoothSide` values instead of linearly inventing them. Character-specific move coefficients and uncaptured proc rates remain estimates or explicit omissions. |

Fate Episodes expose the audited 2.0.2 catalog and an experimental selectable writer for the 319 `3502` episode states and 56 `2561` mission states; only the known completion values are accepted. | Combat reference catalog | Unpacked 2.0.2 damage/guard configuration, 1,905 character damage-limit rows and seven conditional curves are available in loadout inspection. Raw nodes and exact `attackRate=1.0` table rows are shown without inventing unknown interpolation or final per-action caps. |
| Current-session damage capture | The integrated runtime can capture the 2.0.2 `ProcessDamageEvent` stream into a fixed 4,096-row shared-memory ring buffer. The app reports raw action IDs, exact pre-cap/cap comparison, overwritten-row counts and source-separated action summaries, and restores the owned Hook on explicit stop or app shutdown. Player/pet/summon ownership is not yet field-closed, so the UI labels totals as a global unattributed observation rather than personal DPS. |
| Game convenience runtime | One persistent integrated session owns damage-cap percentage display, decimal enemy HP/SBA display, room-ID capture with automatic clipboard copy and main-story Captain replacement. ## Field evidence captured

- Io final HP was read repeatedly from the running game, including the stable `126,645` snapshot used to validate the monitor lifecycle.
- The Io EX node `1F52146F` is stored as float32 `0.4` but produces `+4` on the displayed stun scale; the versioned calibration record keeps the raw and displayed units separate.
- A repeated training-area comparison observed the same incoming attack with and without Defense +5%; the result is consistent with percentage damage reduction for that sample.
- Automatic perfect guard was retested after adding the second guarded site used during combo continuation.
- The monster HP, damage, stun, overdrive and one-shot empty-overdrive patches were installed and restored in one live 2.0.2 session; all original-byte and readback checks passed.
- The current-session damage runtime completed a live 2.0.2 start/status/stop lifecycle against PID 25660; the shared-memory protocol became active and the status returned to `inactive` with “hook restored after active callbacks drained”. No combat event attribution was claimed by this lifecycle-only check.
- Earlier convenience-runtime experiments completed six 2.0.2 install/restore lifecycles, including level-sync and wrightstone-return hooks. Those runs proved only lifecycle restoration, not correct gameplay effects. The two mutating features are disabled in the current build until their effect-level acceptance requirements are met.
- After stale `inactive` status handling was fixed, the current embedded runtime repeated session-only, free-Captain, display/session and all currently enabled features against the same live 2.0.2 process. All four combinations reached `active`, returned to `inactive`, released ownership and left the game running.
- The integrated audio and camera runtimes both completed a fresh 2.0.2 enable/disable lifecycle against PID 25660 and restored their owned hooks. The installed English/Japanese voice-bank validator passed 76,845 assertions; UI effects were independently discovered from the eight `ui*.bnk` banks and are not mixed into character voice ownership.
- The integrated virtual-sigil runtime completed a fresh enable/disable lifecycle against PID 25660 and returned its getter hook and native loop limits to `inactive`. Character switching, scene switching and same-character teammate isolation still require visible quest samples.
- The spatial page repeatedly read stable town coordinates, completed a no-displacement write/readback at the same coordinate, survived page navigation and restored its capture hook on disconnect.
- The previous camera runtime applied distance `9` and target height `2.6` in the live 2.0.2 camera object with write-back verification; an earlier `12`/`3.4` configuration and a subsequent hot update were also observed. Those observations must be repeated after the native-runtime migration.
- The game enumerated all eight configured virtual slots and served them from distinct real inventory instances (`SlotID 60103`, `60124`, `60126`, `47506`, `48314`, `54651`, `54735`, and `54736`) after the local status rebuild. The component loaded from its canonical directory without a stale replacement path or missing-DLL warning. The field configuration was restored to the four-slot default after the pressure test.
- The opt-in live release acceptance harness now fails, rather than skips, when its save-backed virtual-sigil case or stable-player spatial case cannot run. Its camera, audio, QOL, damage-capture, virtual-sigil, and spatial/gravity lifecycle cases all passed in one supported 2.0.2 process and restored their owned state.

## Still open or only partially closed

| Request | Honest boundary |
| --- | --- |
| Complete SDK/game dump | Not performed and not required by the released application. Checked-in data comes from selected extracted tables, guarded executable sites, save layouts and field samples—not a claim of complete engine metadata. |
| Every character’s exact final formula | The common v2 damage and mitigation equations now participate in character-direction Top 10 ranking. The inventory domain varies owned equipment and sigils; catalog/table domains keep equipment fixed. Inventory mastery candidates are the presets actually saved for that character, not every mathematically legal mastery-node combination. Per-action coefficients, exact final caps outside recorded table nodes, character mechanics and several weapon/wrightstone/summon effect atoms are still incomplete, so the UI labels the result as a formula model rather than a proven global optimum. |
| Mastery unlock boundaries for every save state | Structural rank pools and save-backed caps are implemented. The full matrix of unopened, zero-MSP, low-rank and max-rank saves has not been field-sampled across multiple saves. |
| All permanent character growth | Extracted AP-tree/panel contributions are included where mapped. Irreversible growth and character-specific exceptions still require paired saves or cross-character evidence. |
| Defense and support interactions | The +5% sample is field-verified; the broader set of defense masteries, buffs, reductions and support interactions has not been generalized from that single sample. |
| Damage cap and conditional skills | Represented as separate sources/candidates, but battle/dummy samples are still required for exact effective caps and conditions. |
| Every runtime patch in every scene | Catalog guards and automated lifecycle tests exist for all published entries; only named critical paths have repeated live-game evidence. |
| Personal/team attribution for current-session damage | Raw source instances are separated so identical action IDs from different sources no longer merge. Mapping pets, summons and remote players back to stable party identities still requires live quest samples; until then aggregate damage and DPS remain explicitly global and unattributed. |
| Unlocking absent DLC systems | The tool can edit encodable records but intentionally does not promise to set every progression flag needed to unlock systems the save has never opened. |
| Fate Episode write evidence | The experimental writer exposes only explicitly selected `3502` Fate states and `2561` mission-completion fields, bound to the inspected file revision. Real-save copies pass backup, atomic write, reopen, per-field readback, stale-revision rejection and forced-readback rollback tests. Secondary statistics/notification families such as `5801/5815`, claim states and dependency flags remain untouched and unproven, so the UI states that game effects and reward claiming are not verified. |
| Final action damage caps | Global baselines, character tables and raw conditional nodes are available. Action-specific producers and `Smooth`/`SmoothSide` interpolation are not proven, so the UI does not claim an exact final cap. |
| Endless task behavior | The 25 localized rules and five difficulty rows are exact unpacked references. They document task behavior but do not prove a runtime task hook or positive Conflux-timer activation inside a real Endless quest. |
| High-risk runtime experiments | Continuous world-axis coordinate flight and independently controlled gravity suppression are implemented with process ownership, exact 2.0.2 executable identity, byte validation, read-back and detach recovery. This is still not noclip and needs scene-switch field acceptance. Natural-drop deployment validates all eleven exact 2.0.2 source tables used by its summon, Transmarvel sigil, wrightstone and Forger's Bounty item-package outputs, preserves unrelated `data.i` fields, rejects conflicting external entries and uses a verified backup for one-step restoration. Wrightstones are limited to the original four families, three variants per family and the legitimate 20/15/10 result shape; live forge acceptance remains pending. Regular items are limited to the one verified Forger's Bounty package rather than presented as a global quest/enemy/chest/event drop override, and their live package outcome also remains pending. Audio, town-camera and virtual-sigil helpers share the integrated native runtime and fail closed. Audio covers uniquely attributable character-bank events and explicit UI banks while leaving shared/unknown events unchanged; English/Japanese bank parity and runtime restoration passed. Camera and virtual-sigil explicit disable passed after migration, but scene switching, teammate isolation and broader Hook coexistence still need visible gameplay samples. Virtual slots extend native runtime trait enumeration with 1-8 configured real inventory instances and never extend the save's 12 physical slots. Noclip remains unavailable. Level sync and wrightstone return are hard-disabled pending effect evidence; main-story formation behavior remains an effect-level acceptance item. |

The application must continue to label unresolved values as estimates, candidates, negative observations or open evidence. A green unit test proves a software contract, not a previously unobserved game formula.
