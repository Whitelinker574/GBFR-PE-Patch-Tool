## 游戏 2.0.3 适配说明

v2.0.4 已重新解包并逐文件核对游戏 2.0.3：2,120 张核心表中只有 4 个本地化文本包变化，项目使用的因子、祝福、召唤石、掉落、武器、伤害上限、角色成长和无尽规则表均与 2.0.2 逐字节一致；332 份角色与战斗配置也全部一致。

因此，内置目录、配装编辑与优化、分享码/二维码/分享图、Logs 和不依赖游戏进程的离线流程可以继续使用。游戏 EXE 的地址已经迁移，所以实时编辑、队友进程采集、运行时补丁、镜头/音频 Hook 和 `data.i` 天然掉落部署在 2.0.3 上暂不开放。应用会在共享连接入口识别新版 EXE 并拒绝旧地址写入，不会先连接后碰运气。

完整证据和仍待实机验收的项目见 [游戏 2.0.3 一手资料核查](docs/GAME_UPDATE_2.0.3_OFFICIAL_RESEARCH.md)。

## 先说清楚它能做什么

v2.0.3 把原来的存档编辑器扩展成五个按实际使用流程排列的工作区：

| 工作区 | 适合做什么 | 数据边界 |
| --- | --- | --- |
| 存档与配装 | 编辑角色、武器、因子、祝福、召唤石和配装；比较两份存档 | 离线写入，写前备份，写后重新打开并回读 |
| 游戏内即时编辑 | 修改当前选中的因子、祝福、召唤石和角色上限突破 | 需要连接游戏；每次写入都绑定当前进程和捕获对象 |
| 配装采集与复刻 | 持续采集队友配装，导入 Logs JSON/数据库，查看战斗档案 | 采集默认关闭，用户点击后才持续运行 |
| 单机运行时工具 | 显示、房间号、队长、坐标、音频、镜头和战斗规则等 | 只面向单机/主机端；未完成实机证据的候选入口保持禁用 |
| 游戏文件、诊断与设置 | 天然掉落规则、只读公式采样、版本诊断、语言与设置 | `data.i` 部署会备份并提供恢复；诊断页不会写游戏 |

页面上的“离线”“实时”“只读”“实验”“未开放”不是装饰。它们分别说明数据会写到哪里、是否需要游戏进程，以及当前证据能支持到什么程度。

## v2.0.3 最值得先体验的内容

### 在角色配装里按技能目标自动选因子

智能配装已经放回角色配装详情的因子区域，不需要再去找独立工具页。

<p align="center">
  <img src="docs/screenshots/v2.0.3-smart-loadout.png" alt="按技能目标配装入口与目标设置" width="960">
</p>

你可以在“手动配装”和“按技能配装”之间切换：

1. 选择任意数量的技能并填写目标等级；
2. 系统按从上到下的优先级处理目标，优先使用当前存档背包中的真实、互不重复因子；
3. 十二槽无法满足全部目标时，会明确告诉你从哪一项开始无法继续、缺少哪些因子；
4. 需要制造的缺口会单独标出，只有确认后才创建新的合法实例；
5. 结果先回填到配装草稿，最后仍由你决定是否写入存档。

自动推荐还提供 29 名角色的可追溯参考路线，以及攻击、防御、昏厥、续航、药水/复活、闪避循环等方向变化。它们会结合当前库存、角色特性、伤害上限和已收录的 2.0.2 证据进行排序，但不会冒充“所有动作、所有条件下的数学绝对最优”。

### 点击一次，持续采集每场队友配装

<p align="center">
  <img src="docs/screenshots/v2.0.3-party-capture.png" alt="队友配装持续检测与历史" width="960">
</p>

队友配装检测默认不会自行启动。点击开启后，它会作为后台服务保持连接，等待连续三次稳定快照，再把每场可确认的 2–3 名队友配装存入本地历史。切换页面不会停止采集，直到你主动关闭。

同一工作区还可以：

- 粘贴 Relink Logs 角色 JSON，或选择 `logs.db`；
- 浏览 Logs 战斗档案、队伍伤害、技能明细和配装快照；
- 预览、导出、部署或上传已经确认的候选配装；
- 对真正没有记录的武器、祝福、召唤石或专精显示“未记录”，不拿其他角色的数据补齐。

当前会话伤害仍只能称为“全局未归属观测”。本机、队友、宠物和召唤物的稳定归属尚未闭环，因此不会显示成虚假的个人 DPS。

### 分享码、在线图鉴和分享图

相同配装正文会得到稳定短码，服务端会对相同不可变配装帧去重。角色配装卡片会直接显示本次运行中已上传的短码，并提供上传或复制入口；重启后再次点击上传即可通过服务端去重复用同一配装正文。收到带二维码的配装图时，可以在配装工作台的“分享码”中选择图片，本地识别后进入分项导入确认；图片不会上传。关闭“公开上传”时，不会把配装偷偷放进公共目录。

公开图鉴支持搜索角色、武器、因子、祝福、召唤石、专精和技能；默认按最新发布排序，也可按名称或点赞数排序。配装卡片可以直接点赞，再点一次即可取消。

分享图工坊使用清透空域、星图花纹和大幅角色立绘，完整展示武器、十二因子、技能摘要和二维码。横版 `1920×1080`、竖版 `1440×1920`、方形 `1600×1600` 可直接切换；窗口预览会自动缩放，下载 PNG 保持真实像素。网络失败时仍可使用离线长码或 JSON 文件。

### 在同一页比较并复制两份存档

<p align="center">
  <img src="docs/screenshots/v2.0.3-save-diff.png" alt="双存档差异与同页复制" width="960">
</p>

存档实验室会并排显示两份存档的差异，并按角色成长、配装、物品、任务状态和未知结构分类。已确认语义、结构一致的记录可以直接选择左右写入方向；单侧新增、删除、长度变化和未知结构保持不可复制。

命运篇章提供受限实验写入，只处理已经审计的篇章完成值和任务完成值。奖励领取、章节依赖和游戏内效果仍未宣称完成。无尽模式规则目前是双语只读图鉴，没有安全的部署和回读链路就不会伪造编辑按钮。

### 使用内置 2.0.2 表配置天然掉落

<p align="center">
  <img src="docs/screenshots/v2.0.3-natural-drop.png" alt="天然掉落与锻造规则" width="960">
</p>

召唤石、因子、祝福石和已验证普通物品奖励都从应用内置的精确表中选择，不再要求用户自己寻找解包目录。先选择种类和词条，再加入“待部署清单”，部署前可以逐条核对。

普通物品目前只接入已验证的无尽模式“锻造师奖励”物品池，不是全任务、敌人、宝箱和活动的通用掉率修改器。天然因子、召唤石掉落和祝福石锻造的真实游戏结果仍需要更多现场样本，所以该页继续标为实验，并始终提供 `data.i` 备份与恢复。

## 写入和恢复规则

离线存档写入统一经过：

1. 创建可恢复备份；
2. 在临时文件中修改；
3. 校验并修复校验和；
4. 原子替换目标文件；
5. 重新打开并逐字段回读。

实时功能统一绑定完整的 `{PID, creation time}`，启用前校验游戏 2.0.2 EXE、签名和原字节，写后回读；停用、断开和退出时恢复。游戏 2.0.3 会在共享连接入口被明确识别并拒绝旧运行时写入。F12 可以集中停止后台采集、移动和内置运行时。

请仍然手工保留重要存档副本。游戏更新后，在仓库明确确认兼容之前不要继续使用实时写入。

## 正式版仍保留的诚实边界

以下内容没有被 v2.0.3 公告包装成“已完成”：

- 低配目标机长时间运行与真实 QQ 图片往返；
- 所有角色的完整动作系数和最终动作上限；
- 本机、队友、宠物和召唤物的稳定伤害归属；
- 命运篇章领奖状态和完整章节依赖；
- 天然召唤石/祝福石/因子的实际掉落与锻造验收；
- 虚拟因子切角色、切场景、同角色队友隔离和多 Hook 长测；
- 音频多场景听感、城镇镜头迁移复验；
- noclip 和相机相对飞行。

冷却倍率、共享蓄力、候选怪物全队伤害、候选补丁和新的虚拟因子会话在正式版中保持禁用。保留页面是为了说明证据、预览配置或恢复旧测试会话，不代表可以安全开启。

## 性能与兼容

- Windows 10/11 x64；游戏 2.0.3 支持静态目录、离线存档、配装、分享与 Logs，实时功能仍锁定已验证的 2.0.2；
- 最小窗口 960×640，覆盖常见宽屏和 100%/125%/150% 缩放布局；
- 初始 JS/CSS 已拆分为按页加载，配装求解在可取消的 Web Worker 中运行；
- 存档差异单份最多 64 MiB；Logs 文件、记录和解压数据都有明确上限；
- 参考机打包版在 960×640 和 1280×800 的 50 次热切页 P95 均低于 300 ms；
- 28 个页面目的地、两种语言、七种窗口与三档缩放完成 1,176 个浏览器壳场景检查。

详细测量方法见 [性能基线](docs/PERFORMANCE_BASELINE.md)。

## 快速开始

1. 从 [GitHub Releases](https://github.com/Whitelinker574/GBFR-PE-Patch-Tool/releases/latest) 下载 `windows-amd64.exe` 或 ZIP；
2. 第一次使用先进入“存档与配装”，确认工具识别到正确的 `SaveData` 槽位；
3. 离线编辑前退出游戏，完成预览后再确认写入；
4. 实时功能先启动游戏，再在对应页面点击连接；用完点“停止/恢复”；
5. 如果启动失败，查看 `%LOCALAPPDATA%\GBFR-PE-Patch-Tool\startup.log`。
